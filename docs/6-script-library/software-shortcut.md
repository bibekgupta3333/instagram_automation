## C02-01 — Why Your Sheet Counts One Request Twice

**Format & length:** Standard 16:9, 6:00; 40s vertical excerpt.

**Evergreen angle:** What makes two records the same? Refresh function behavior and import UI.

**Title & thumbnail A/B:** A: “Why Your Sheet Counts One Request Twice”; focal duplicated row, “Same request?” B: “Choose a Better Duplicate Rule”; focal branching ID card, “Which identity?”

**Hook (0:00–0:10):** “These rows look identical. Deleting either one could be a mistake.” Open tightly on two synthetic workshop requests.

**Attention magnet:** Which field distinguishes repeat work from duplicate entry? Resolve at 4:40.

**Story beats:** 0:00–1:00, visual mystery: scan matching names and dates. 1:00–2:10, reveal different request IDs through a pan; “A matching name is a clue, not an identity.” 2:10–3:25, propose COUNTIF flags on IDs and inspect deliberate repeats. 3:25–4:40, complicate with two legitimate requests from one person; compare whole-row cleanup as a fair option for exact copies. 4:40–6:00, rebuild the rule around request identity, preserving raw input; “Decide what a row means before deciding what disappears.”

**Payoff & final line:** Duplicate rules depend on the record's unit, not appearances. “Count the request, not the resemblance.”

**Short cut:** Matching rows → contrasting IDs → flag repeated IDs while preserving distinct requests.

**Evidence & rights:** S1: verify COUNTIF, UNIQUE, blanks, and whitespace. Author the dataset, formula annotations, and screen capture; stage all examples as synthetic, not customer findings.
